# GD1 — Global scene colour grading

**Status:** C# + shader source integrated 2026-10-31, Godot 4.7/.NET local build + visual acceptance pending.

- `WorldColorGrade.cs`: scene-owned `CanvasLayer` **layer 0** with a full-screen mouse-ignored `ColorRect`. Only visible if one grading setting differs from neutral and settings are enabled. It therefore costs **no screen pass at neutral**; when edited, one low-cost but full-screen shader pass runs each frame. No `_Process`/_PhysicsProcess, no continuous C# refresh.
- `Shaders/GlobalColorGrade.gdshader`: samples Godot 4 `hint_screen_texture` using `SCREEN_UV`, rotates hue using YIQ chroma axes, adjusts saturation, contrast and brightness. This is a post-tonemap **display-space** effect; not HDR exposure, LUT-based grading or filmic tonemap replacement. Avoid extreme hues/contrast values if posterization appears.
- `Configuration/WorldColorGradeSettings.cs` and `ColorGradeMaster.tres`: enabled but neutral by default (Hue 0°, Sat 1, Contrast 1, Brightness 1). Persistent defaults are authored here; F1 affects a runtime deep duplicate only.
- `DEBUG/Overlay/DebugOverlay.cs`: **F1 → Colour grading** controls with live callbacks, values added to Copy settings. Shared FPS/top-down scene uses exactly one grading layer. HUD is in CanvasLayer layer 2; debug UI at layer 1, right spawner at layer 20, so those labels/buttons are not graded. The gameplay world, weapon model, terrain, fog and sunlight are graded together; independent Sky3D atmosphere and lighting resource settings remain separate.

**F1 UX:** WorldController is now the sole F1 owner. It displays both left settings and right spawner at once, or hides both for a clear view. On game startup both panels begin hidden **after** terrain/actor checks, leaving meaningful startup error text visible if an early return occurs. Escape/right Close hides both; F1 toggles both. Spawner preview objects remain in the game on UI closure, by design. When FPS mouse was captured when opening, closing via F1 recaptures it.
