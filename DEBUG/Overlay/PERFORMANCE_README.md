# PERF0 — F2 performance diagnostics (2026-10-31)

This is an **opt-in in-game diagnostic**, independent of the larger F1 tuning overlay and the Godot Debugger Profiler. It reports frame intervals, slowest timed C# chunk/scene operations, recent expensive calls and the number of currently resident foliage chunks / WS2 buildings.

- **F2** toggles the top-right panel and starts a fresh capture. F2 again hides it and stops timing. The UI samples frame intervals while visible; the static Stopwatch scopes are effectively no-ops when F2 is hidden.
- **Measured operations:** `StylizedGrassPlacement.CreateChunk/ReleaseChunk`, `PinePlacement.CreateChunk/ReleaseChunk`, `ForestPlacement.SyncChunks/CreateChunk/ReleaseChunk`, `ContentScatter.CreateChunk`, and `StaticSectionStreamer._Process` (one WS2 step). Their boundary-only Grass/Pine/Rocks reconcile methods are also timed to reveal the cost of many individually cheap chunks in one crossing. Each uses an existing main-thread entry point; no chunk algorithms, physics, LOD ranges or work budgets were changed.
- **Frame time** is estimated from a Godot `_Process(delta)` interval, which includes scheduling and can be affected by alt-tabbing, vsync and editor overhead. It is not a line-by-line engine CPU profile. Threshold: 40 ms. Green/red history covers the last 240 rendered frames, not a fixed number of seconds.
- **Measured C# timing** uses `Stopwatch.GetTimestamp` scopes and is **inclusive**. `Forest.SyncChunks` includes its child `Forest.CreateChunk` calls; **do not sum their times** as separate costs. For very many small calls, look at repetition counts and use Godot's built-in profiler for overall frame/physics/GPU breakdown. The most expensive call is a lead, **not definitive causality** for a displayed frame spike.
- **Recent operations** retain only the latest 12 calls taking >=2 ms; the panel shows the newest five and the per-operation worst/last timings since F2 opened. There is no disk logging, per-frame JSON, scene-tree crawling or full-world actor scan.
- **Render/physics/GPU** are not isolated by these user-code scopes. Investigate Godot Debugger > Profiler, Visual Profiler, Monitors and repeated Errors alongside this panel when no C# timings explain a hitch. It does not time Terrain3D internals or Godot physics.
- **Current known suspects** from `myownnotes.md`: multiple foliage generation owners responding to the same 32m crossing, plus optional rock collision and up to 20 extra store stress zombies. Check whether the high frame time coincides with the newly displayed measured operations, then toggle vegetation families individually using existing F1 controls as a controlled A/B check.

Confirm counter changes and timed calls, then close F2 and check normal gameplay. Keep F1 behaviour unchanged. In-game profiler/visual acceptance pending until locally tested.
