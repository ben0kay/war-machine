# STG1 — imported ForestGrass001 patch placement

**Status: source implemented, awaiting local Godot/.NET and visual/FPS validation (2026-10-30).** Enabled by default in `Configuration/StylizedGrassMaster.tres`; old TerrainGrass GPU-particle emission is OFF in both `VEGETATION/Configuration/VegetationMaster.tres` (top-down) and `VEGETATION/Grass/FirstPerson/GrassMaster.tres` (FPS). Old implementation files remain as an optional fallback.

## How the world uses the pack

- `StylizedGrassPlacement.cs` reuses the **six** original `ASSETS/Vegetation/Grass/ForestGrass001/Models/forest_grass_001_{a,b,c}_LOD{1,2}.gltf` models; imports one `ArrayMesh` per variant/detail *once at startup/rebuild*, uses the source texture atlas/vertex colours through a shared ShaderMaterial, then batches all patch clumps via `MultiMeshInstance3D`. No one-node-per-grass, GPUParticles3D, terrain paint or new model copies are required.
- Deterministic `Seed=49117`; each 32m chunk tries six patch centres (82% probability each), around twelve clumps per patch within an irregular ~1.7–3.6m radius. Each clump randomly rotates/scales (0.75–1.15). Individual roots are projected onto saved Terrain3D and rejected if missing/too steep. **These are candidate targets, not guaranteed counts**; Output/scene-tree inspection and user visuals are the authority.
- The existing `VillageLayout.GrassClearings` includes **all authored village roads, paved platform/building envelopes**, with small margins. `WorldController` hands exactly those rectangles and legacy scenery/deer clearing masks to `StylizedGrassPlacement.ExclusionAreas` before first chunk generation. Every clump checks an extra **0.9m × its scale** around its root to avoid foliage visibly crossing road/sidewalk edges. This is world-XZ authored rectangle filtering, not general navmesh or material/texture detection; if new roads are added later, include them in `GrassClearings`.
- LOD1 draws until ~28m, LOD2 from ~28–64m using native visibility range of chunk-owned `MultiMesh` batches; no per-clump CPU distance checks. Actual switch distance is measured from each *batch bounds*, not each blade. Render radius/LOD, scatter amount, patch size, slope, edge clearance and scale are editable in the grass master.
- No grass colliders or physics queries. No per-frame C# `_Process`/`_PhysicsProcess` for this grass. On a player crossing a **32m** chunk boundary, a limited neighbourhood loads/unloads; re-entering identical chunk seeds gives the same patches. Idle player = no placement processing. Wind motion is an inexpensive shader effect (GPU TIME), with initial wind values from existing environment settings and explicit `ApplyWind` for settings changes. Terrain3D heightmap changes trigger one rebuild via signal.
- The original old debug F1 grass quality/density panel still addresses `TerrainGrass`, which is now **disabled**. It does not yet control `StylizedGrassPlacement`; edit `Configuration/StylizedGrassMaster.tres` and reload for density/patch changes. Avoid activating the old grass via F1 while comparing, or both systems could appear.

**Shared foliage tint (STG1):** Under Godot **Project → Project Settings → Shader Globals**, edit `wm_foliage_tint` (Color, default muted green `0.43,0.55,0.37`) and `wm_foliage_tint_strength` (float, default `0.25`, 0=no tint). These real Godot 4 shader-global uniforms are defined in `project.godot` and read by both stylized grass and the imported stylized pine foliage shader; the DF2 broadleaf crowns also use them. They are **not one shader/material**: tree and grass keep their own mesh, textures, vertex colours, wind and local palette response. For other imported vegetation to participate later, its shader must declare/read the same global uniforms. The source `ASSETS` models/materials were not edited.

## Configuration & acceptance

Open `Configuration/StylizedGrassMaster.tres`. `Enabled=true` is authored; reduce `PatchChance` or `ClumpsPerPatch` for less grass, alter `PatchRadiusMin/Max` for wider/narrower clusters, `RenderDistance` for cost and `LodDistance` for imported LOD switching. To restore old GPU particles: set `Enabled=false` in this master, set `Enabled=true` in both old `VegetationMaster.tres` and FPS `GrassMaster.tres`, then restart your scene.

**Local check:** pull `implement-td0-td1`, let Godot import all six grass glTF models/atlas, `dotnet build war-machine.csproj`. F6 both `WORLD/FirstPerson/FirstPersonWorld.tscn` and `WORLD/World.tscn`. Inspect road edges/building footprints, steep terrain, mesh texture/colour, tiny gaps between patches, LOD around 28m, wave direction, palette changes in Project Shader Globals, world-chunk crossings and stable seeds on reload. Ensure no `GrassTile*` GPUParticles3D exist, no new grass collision and FPS remains acceptable. Measure same FPS camera angle with new vs old / OFF as needed; performance has **not** been measured remotely. Changes to village masks after startup require reload/rebuild.

**Scope:** doesn't alter roads, buildings, cliff terrain/terrain material, trees, DF2 forest placement or existing grass source meshes/textures. No global actor state/simulation.

## STG3 — widespread billboard filler (2026-10-31)

**Source integrated; awaiting local Godot/.NET, visual and FPS validation.** The existing clumped ForestGrass001 (A/B/C, two LODs) is unchanged. A separate enabled `Configuration/BillboardGrassMaster.tres` overlays `ForestGrass001_Billboard` A/B/C crossed-card meshes as **widespread ground filler**, not patches. Filler uses independent jittered cells with independently rejected candidates, varied yaw/scale and a different seed; there are no patch centres. The default 1.8m cell size and 82% occupancy attempt about **266 billboard roots per 32m chunk**, before terrain/road/building rejection. This is a starting performance/visual baseline, not a guaranteed count.

Both layers share one `StylizedGrassPlacement`, the existing player-driven chunk residency, saved Terrain3D slope/height queries and **the exact same `GrassClearings` masks** from village roads, paved building platforms, cliff and deer reservations. Filler has its own editable edge clearance (0.65m × scale), minimum terrain normal, scale range, wind multiplier, enabled toggle, seed, cell size and coverage. No grass colliders, particles, per-grass nodes, per-frame C# loops or independent streaming range. Each present variant uses **one** new MultiMesh batch per chunk, sharing its own billboard atlas/material across all chunks, with shadows disabled. The material participates in the same `wm_foliage_tint` shader globals as the original grass.

Filler uses **the global GV1 fog envelope** for its single mesh LOD, rather than inventing a grass-specific draw distance. Shorter opaque fog trims billboard batches and resident chunks; longer fog extends them. The authored billboard material has its own texture atlas and cutout alpha; do not reuse the original ribbon grass material. On chunk exit all filler batches are released, and re-entry recreates the same deterministic positions. F1's existing Grass sliders continue to control the clustered grass only; filler configuration is edited in `BillboardGrassMaster.tres` and reloaded with the scene. Turning clustered grass off does **not** switch off filler; disable both resources to turn off both layers. Turning off just filler leaves original grass untouched.

**Local acceptance:** pull the active branch, allow the billboard glTF/atlas and C# class to import, run `dotnet build war-machine.csproj`, then F6 on `WORLD/FirstPerson/FirstPersonWorld.tscn`. Check that grass is scattered widely without discernible clusters/grid, building interiors and roads remain bare, foliage tint and wind behave, no obvious billboard cutout squares appear close up, and unchanged original clumps remain. Compare F2 frame times with filler on/off at the same camera positions and fog distances (e.g. 50/115/200m), check 32m crossings and stable seeds. **Rendering performance and shader compilation have not been verified remotely.**

## STG3B — billboard grass reset to large variable patches (2026-10-31)

**Current implementation, replacing the STG3 jittered-cell algorithm above; awaiting local build/visual/FPS validation.** This changes only the `ForestGrass001_Billboard` distribution and authoring controls. The existing original stylized ForestGrass001 A/B/C clumps, textures and two authored LODs are untouched. STG3B uses **9 seeded patch attempts per 32m chunk**, 90% patch chance, and **28–64 billboard instances in each accepted patch**. Candidate count averages about **373 billboards per chunk** *before* road/building/slope rejection. A patch radius varies **2.2–7.2m**, with random elliptical aspect and heading plus subtle multi-lobed edge variation, so the density makes large irregular grass stands rather than a repeated cell grid or perfect circles.

Each billboard gets independent A/B/C variant, yaw and **0.60–1.55× individual scale**, further biased by a **0.82–1.18× per-patch scale** so some patches are visibly taller and others shorter. **35%** of accepted candidates receive an extra **0–5° tilt about a random horizontal axis**, in addition to the authored cards' existing lean. Rotation is applied to the instance basis without moving its root below ground. Size-aware road/building clearance defaults to **0.75m × scale**, and the same Terrain3D height/slope checks remain. Mesh/material/atlas, GPU MultiMesh batching, shared wind/tint, native global fog range, 32m streaming and chunk-determinism are preserved. No new collision, per-instance nodes, per-frame processing or separate grass distance overrides.

Tune the new fields in `Configuration/BillboardGrassMaster.tres`: `PatchesPerChunk`, `PatchChance`, `MinPerPatch`, `MaxPerPatch`, `PatchRadiusMin/Max`, `ScaleMin/Max`, `TiltChance`, `MaxTiltDegrees`. The STG3 `CellSize` and `Coverage` controls are **removed**; the previous STG3 widespread-filler text is historical. Billboards remain independently toggleable and use their existing seed. The original grass F1 controls still change only the original stylized patches; adjust billboard defaults in its master and reload.

**Local checks:** `dotnet build war-machine.csproj`; F6 `WORLD/FirstPerson/FirstPersonWorld.tscn`. Walk around village pavements/buildings and hillside, check large irregular billboard stands of mixed sizes, some subtle lean, no grass intersecting buildings or roads, correct wind, shared tint and fog visibility, identical patch positions after leave/re-enter. Compare F2 frame times at identical views with billboard Enabled ON/OFF (and at shorter/longer fog); alpha-tested surface overdraw can still cost GPU time even at 6 triangles each. Validate both original grass visuals and zombie/player interaction separately. **No remote Godot compilation, visual or performance acceptance.**
