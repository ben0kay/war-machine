# Vegetation configuration

**GV1 authoritative visibility master:** `VegetationVisibilityMaster.tres` contains **all active vegetation visibility and LOD-distance tuning**, shared by scattered pines, DF2 broadleaf trees, stylized imported grass and the new billboard filler layer. Individual masters contain only placement, art, collision, shadows, seeds and chunk-size parameters; no visibility-range properties.

## GV1 — One global fog-linked vegetation range (2026-10-31)

**Current authoritative behaviour:** the scattered pine forest, DF2 dense canopy, imported ForestGrass001 grass and billboard filler **no longer have individual render/LOD distance fields**. They all use `VEGETATION/Configuration/VegetationVisibilityMaster.tres` through one shared `VegetationVisibilityPolicy`, bound to the active `PlayerDistanceFog` profile in `WorldController.InitializeRenderPolicy` for both FPS and overhead world.

- **Fully opaque distance fog ON:** effective vegetation disappear range = `PlayerDistanceFog.OpaqueRadius + FogSafetyBuffer` (24m initially). There is **no separate maximum** that can clip vegetation sooner than the fog; making fog shorter reduces visible batches and loaded chunks, making it longer extends them.
- **Fog OFF or not fully opaque:** the one fallback range is `NoFogDistance=160m`; changing this setting does not create a second active vegetation-specific range.
- **Global LOD bands:** LOD0 ends at 35% of the effective range; LOD1 ends at 70%; LOD2 (for the 3-model stylized pines) continues to the global disappearing boundary. Two-model DF2 and imported grass use LOD0 to the first threshold and their last available LOD until the same boundary. The single-LOD billboard filler stays drawn to that same global boundary. Older procedural/GLB pines retain their current number of actual mesh levels. A shared 6m native range-transition margin applies.
- **Safe streaming:** on fog-setting changes the shared policy fires one event; existing `PinePlacement`, `ForestPlacement` and `StylizedGrassPlacement` (including its billboard filler) update active native MultiMesh range fields and reconcile their loaded chunk neighbourhood. None adds per-tree CPU LOD, `_Process`, recurring timers or per-frame scene-tree queries. Seeded geometry, masks, trunk collision, chunk-size tuning, sunlight and materials remain unchanged.
- **F1 readout:** under Foliage → **Shared fog-driven visibility**, the distance and two LOD thresholds update when the fog slider changes; Copy settings reports `VegetationRenderDistance`, `VegetationLod0End` and `VegetationLod1End`. The authoritative FPS slider is **F1 → Environment → Distance fog → Fog fully opaque (m)**. Top-down follows its own shared world fog profile.

**Visual caveat:** FPS uses a partially clear sky behind its depth-overlay fog (`FpsSkyFogOpacity` defaults to 0.08). Removing an opaque tree behind the geometry fog may expose clearer sky at silhouettes; this is a known reason the older WS1 policy would not aggressively cull such geometry. The 24m visibility safety band mitigates but does not mathematically guarantee invisible removal at every screen pixel. If you see sky-shaped popping, consider adjusting FPS sky-fog opacity or a geometry fade before further reducing the buffer. We intentionally have *not* globally changed the sky/atmosphere appearance.

**Verification required:** compile `war-machine.csproj`, run both worlds with F6, enable FPS distance fog, try end distances ~50/115/200m. Confirm all three vegetation families are visible up to fog and unload behind it, with synced LODs; F1 debug readout tracks immediately; no gaps in grass patches near roads or zombie navigation changes; no tree silhouette holes against the sky; stable frame pacing on slider changes. Fog OFF should restore all three to the one 160m fallback. Local Godot build and visual/FPS profiling were not available during GitHub source editing.

**Legacy particle grass note:** old `TerrainGrass` is disabled in both World/FPS masters but retains historical GPU-particle tiling settings for reversible comparisons. It is **not** part of the active mesh-vegetation policy.

## Historical GPU particle vegetation master

Select `VegetationMaster.tres` in Godot's Inspector for the disabled legacy GPU-particle grass's quality, coverage and appearance controls. This Resource is defined by `../VegetationConfig.cs`. Settings apply on scene launch or an explicit `TerrainGrass.ApplySettings()` call. Density/Enabled=0 completely removes GPU emitters; reapplying nonzero values restores the pool. Wind is owned by EnvironmentMaster. See the parent README for quality multipliers and particle budget behaviour. **These old controls are not authoritative for active mesh grass visibility.**

## FV1 — CPU-owned shared foliage tint, without shader readbacks (2026-10-31)

**Implemented in source, awaiting local Godot/.NET testing.** `FoliageTintSettings.cs` defines the shared tint colour and strength; `FoliageTintMaster.tres` is the new saved **authoritative** default (tint `Color(0.43, 0.55, 0.37, 1)`, strength `0.25`, matching the existing project shader-global defaults). Both active World and inherited FPS use one deep runtime copy created by `WorldController._Ready()`. At startup `ApplyShaderGlobals()` pushes those two values to the existing `wm_foliage_tint` and `wm_foliage_tint_strength` GPU shader globals. **No C# `RenderingServer.GlobalShaderParameterGet` remains** in the active world, F1 panel or DF2 forests.

The same runtime resource is explicitly passed to `ForestZonesPlacement`, which passes it to each `ForestPlacement`. Safe-palette DF2 canopy material initialization uses `FoliageTint.Tint/Strength` without reading the renderer. **F1 → Foliage → Shared tree + grass tint** edits the runtime resource, pushes shader globals using their existing SET API, and updates all safe DF2 canopy materials. The existing Copy settings keys `SharedFoliageTint` and `SharedFoliageTintStrength` now read this runtime resource. Edits are session-only; change `FoliageTintMaster.tres` to persist new defaults. Keep the two global parameter declarations in `project.godot` because foliage shaders still require them; their static editor values are fallbacks, not runtime C# readback sources. No per-frame work, shader changes, tree placement changes, LOD changes, extra scene nodes or colour-grading changes.

**Local acceptance:** `dotnet build war-machine.csproj`; run F6 FPS and World scenes, check the old `global_shader_parameter_get()` errors no longer occur, ensure DF2 safe foliage remains green (not white or black), then adjust tint/strength with F1 and verify grass, billboards, pines and every approved DF2 zone respond together. Copy settings should report the edited values; reloading the scene should reset to master values. Changing `project.godot` shader globals alone is no longer an effective way to author **gameplay scene** startup tint; edit the master instead.
