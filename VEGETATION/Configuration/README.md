# Vegetation configuration

**GV1 authoritative visibility master:** `VegetationVisibilityMaster.tres` contains **all active vegetation visibility and LOD-distance tuning**, shared by scattered pines, DF2 broadleaf trees and stylized imported grass. Individual masters contain only placement, art, collision, shadows, seeds and chunk-size parameters; no visibility-range properties.

## GV1 — One global fog-linked vegetation range (2026-10-31)

**Current authoritative behaviour:** the scattered pine forest, DF2 dense canopy and imported ForestGrass001 grass **no longer have individual render/LOD distance fields**. They all use `VEGETATION/Configuration/VegetationVisibilityMaster.tres` through one shared `VegetationVisibilityPolicy`, bound to the active `PlayerDistanceFog` profile in `WorldController.InitializeRenderPolicy` for both FPS and overhead world.

- **Fully opaque distance fog ON:** effective vegetation disappear range = `PlayerDistanceFog.OpaqueRadius + FogSafetyBuffer` (24m initially). There is **no separate maximum** that can clip vegetation sooner than the fog; making fog shorter reduces visible batches and loaded chunks, making it longer extends them.
- **Fog OFF or not fully opaque:** the one fallback range is `NoFogDistance=160m`; changing this setting does not create a second active vegetation-specific range.
- **Global LOD bands:** LOD0 ends at 35% of the effective range; LOD1 ends at 70%; LOD2 (for the 3-model stylized pines) continues to the global disappearing boundary. Two-model DF2 and imported grass use LOD0 to the first threshold and their last available LOD until the same boundary. Older procedural/GLB pines retain their current number of actual mesh levels. A shared 6m native range-transition margin applies.
- **Safe streaming:** on fog-setting changes the shared policy fires one event; existing `PinePlacement`, `ForestPlacement` and `StylizedGrassPlacement` update active native MultiMesh range fields and reconcile their loaded chunk neighbourhood. None adds per-tree CPU LOD, `_Process`, recurring timers or per-frame scene-tree queries. Seeded geometry, masks, trunk collision, chunk-size tuning, sunlight and materials remain unchanged.
- **F1 readout:** under Foliage → **Shared fog-driven visibility**, the distance and two LOD thresholds update when the fog slider changes; Copy settings reports `VegetationRenderDistance`, `VegetationLod0End` and `VegetationLod1End`. The authoritative FPS slider is **F1 → Environment → Distance fog → Fog fully opaque (m)**. Top-down follows its own shared world fog profile.

**Visual caveat:** FPS uses a partially clear sky behind its depth-overlay fog (`FpsSkyFogOpacity` defaults to 0.08). Removing an opaque tree behind the geometry fog may expose clearer sky at silhouettes; this is a known reason the older WS1 policy would not aggressively cull such geometry. The 24m visibility safety band mitigates but does not mathematically guarantee invisible removal at every screen pixel. If you see sky-shaped popping, consider adjusting FPS sky-fog opacity or a geometry fade before further reducing the buffer. We intentionally have *not* globally changed the sky/atmosphere appearance.

**Verification required:** compile `war-machine.csproj`, run both worlds with F6, enable FPS distance fog, try end distances ~50/115/200m. Confirm all three vegetation families are visible up to fog and unload behind it, with synced LODs; F1 debug readout tracks immediately; no gaps in grass patches near roads or zombie navigation changes; no tree silhouette holes against the sky; stable frame pacing on slider changes. Fog OFF should restore all three to the one 160m fallback. Local Godot build and visual/FPS profiling were not available during GitHub source editing.

**Legacy particle grass note:** old `TerrainGrass` is disabled in both World/FPS masters but retains historical GPU-particle tiling settings for reversible comparisons. It is **not** part of the active mesh-vegetation policy.

## Historical GPU particle vegetation master

Select `VegetationMaster.tres` in Godot's Inspector for the disabled legacy GPU-particle grass's quality, coverage and appearance controls. This Resource is defined by `../VegetationConfig.cs`. Settings apply on scene launch or an explicit `TerrainGrass.ApplySettings()` call. Density/Enabled=0 completely removes GPU emitters; reapplying nonzero values restores the pool. Wind is owned by EnvironmentMaster. See the parent README for quality multipliers and particle budget behaviour. **These old controls are not authoritative for active mesh grass visibility.**
