# Pine trees — seeded world forest

The active `PinePlacement.cs` owns terrain-aware seeded pine spawning, 32m chunk streaming, shared `MultiMesh` batches, slope/terrain/exclusion filters, spawn clearing, per-tree scale/yaw randomness, native distance culling, trunk collision and camera-obstruction fading. **Both top-down and FPS use this same forest.** No world terrain re-bake is needed.

## Earlier PineTree001 GLB comparison (2026-10-28; superseded as default by PINE-ST1)

**Implemented in source; awaiting Godot/.NET build, visual and FPS checks.** The earlier comparison set `Configuration/PineMaster.tres` to `UsePineGlb=true` and `PineGlbScene` pointing to the actual catalogue `PineTree001.glb`. It swaps **only source geometry**, keeping `PinePlacement` as the sole world spawner. The forest continues to use the **same seed, density, spacing, chunk boundaries, Terrain3D height/slope checks, spawn/site/zombie clearings, seed-driven scales and yaw, lifecycle, shadow settings, render distance and WS1 metadata**. It consumes the original variant random roll even though the GLB has a single mesh, so swapping art does not reshuffle tree positions. **No per-tree PackedScene instancing**; the source GLB is loaded/extracted once and reused in GPU MultiMesh groups.

- **Switch to procedural (current workflow):** set both `UseStylizedPine=false` and `UsePineGlb=false` in `PineMaster.tres`, then reload; the legacy GLB setting is an independent alternative. Existing procedurally generated geometry and its near/far LOD remain unchanged.
- **Imported model:** PineTree001, ~14.4m tall, ~5,969 triangles, **5 surfaces** (two bark, three needles). Uses the original 0.8–1.25 seeded scale range and rotational variation; existing `HeightMultiplier` slider also scales imported pines. Additional optional `PineGlbBaseScale` defaults to 1.
- **Camera fade/wind:** The GLB's imported foliage gets a single shared shader per foliage surface, driven by existing per-instance custom data and existing weather wind controls. The opaque bark stays solid. Canopy fade remains an ordered stipple, not transparency. GLB wind is subtle height-weighted sway, **not individual procedural needle flutter**. All foliage materials are configured once per forest rebuild, not per-tree.
- **Trunk physics:** Retain existing per-chunk `StaticBody3D` and per-tree capsule colliders; use the GLB's measured ~0.45m source trunk radius (via `PineGlbTrunkRadius`) and pre-existing `TrunkCollisionHeight`. Colliders scale with seeded uniform model size. No additional physics systems.
- **Rendering:** Imported GLB has **no custom low-poly far-art LOD** in this pass; procedural `UseGeneratedLod` and `FarLeafStride` apply only in procedural mode. Imported mesh may have its own Godot generated LOD if available. Existing render cap/WS1 fog visibility metadata and chunk eviction remain. This preview will likely cost more in heavy forests (5 material surfaces/tree model), and FPS differences are unmeasured.

## Procedural fallback / original tuning

`C/PineMeshBuilder.cs` still constructs organic layered branch tiers, diamond needle sprays and 3 generated variants. **Only active when `UsePineGlb=false`**, or as safe fallback if the GLB is missing/invalid. Its generated near/far LODs use `UseGeneratedLod`, `FarLeafStride`, `LodDistance` (48m) and native range fading. The original shader `Shaders/LeafWind.gdshader` remains unmodified, with wind and camera fade. Existing forest base defaults: ~12–18m size range before random 0.8–1.25 scaling, density 0.55, spacing 20m, RenderDistance 96m, ChunkSize 32m, SpawnClearingRadius 12m, shadows off, collision on physical layer 5. Runtime tuning changes are applied on release, while standing still does no C# processing.

No harvesting, tree destruction, individual-pine Node3D scripts, per-leaf CPU physics, global source-material edits or automatic migration of the standalone F1 GLB asset.

## PINE-OPT1 — 22.3% fewer triangles, unchanged spawning (2026-10-28)

The shared `PineTree001.glb` is now **5,969 triangles instead of 7,679**. All 839 bark/branch triangles and 171 needle tufts are preserved; each tuft has four cross-section rings instead of five. The GLB still exposes **five material surfaces**, so the existing 3 foliage shader assignments, MultiMesh loading, deterministic terrain placement, wind, canopy fade, trunk collisions and render distance remain the same. `UsePineGlb=true` uses the optimized asset as soon as Godot reimports it.

No code/config/shader changes or per-leaf scene nodes were made. Whole-tree MultiMesh reuse is already efficient; separating the same leaves into hundreds of instances can add draw calls without lowering triangle counts. Evaluate both views and the new FPS counter at the same world location; a dedicated simpler distant model remains future work.

## PINE-ST1 — Stylized PineTree001 model-source switch (2026-10-30)

**Source implemented, runtime Godot acceptance pending.** `Configuration/PineMaster.tres` now defaults to `UseStylizedPine=true`. The existing seeded `PinePlacement` (including all building/road/spawn/robot/DF0 clearings) is unchanged for positioning, density, terrain/slope checks, chunk streaming, visibility ownership and one-body-per-chunk trunk physics. Instead of C# geometry, it imports the uploaded models once from `ASSETS/Vegetation/Trees/PineTree001/Models/pine_tree_001_a_LOD{1,2,3}.gltf` and retains two art surfaces (bark / foliage) per LOD. **No model binary, grass setting, world scene, DF2 canopy-forest configuration or terrain file was changed.**

**Three LOD bands (initial tuning):** LOD1 0–40m (5234 tris), LOD2 40–70m (1354 tris), LOD3 70–96m (146 tris), before the existing top-down camera offset. Native visibility ranges handle transitions; no CPU distance processing. New `StylizedLod1Distance` and `StylizedLod2Distance` fields are editable. One near-foliage shadow source only by default; `FarCastShadows` can enable LOD2 but LOD3 remains shadow-off. `StylizedBaseScale=0.8` makes the authored ~22.45m tree roughly 18m before each original seeded 0.8–1.25 scale; `StylizedTrunkRadius=0.64` matches imported base geometry before scaling.

**Shared material adapter:** `Shaders/StylizedPineFoliage.gdshader` keeps vertex-colour palette and source `PineTree001Foliage.tres` tint values, adding only height-weighted wind and existing `INSTANCE_CUSTOM.r` top-down dither fade. Original asset shaders remain unchanged. Top-down opacity updates **all three levels** while bark and native trunk collision stay solid.

**Switchback:** Set `UseStylizedPine=false`; with existing `UsePineGlb=false` the old C# pines return in exactly the same deterministic locations after scene reload. The older GLB option remains available independently. If any stylized LOD import is missing/invalid (not exactly one mesh with 2 surfaces), loader warns and falls back to existing source. No extra per-tree scripts, regular `_Process` or `_PhysicsProcess` callbacks. Tree templates load once per forest rebuild and then share `MultiMesh` groups.

**Local acceptance:** pull latest dev, open Godot and let three glTF imports finish; `dotnet build war-machine.csproj`, F6 `WORLD/FirstPerson/FirstPersonWorld.tscn` and `WORLD/World.tscn`. Compare with switch OFF at same camera viewpoint: tree counts/positions/orientations, 40/70m LOD thresholds, imported vertex colours, collision, top-down fade, wind movement, 32m chunk crossings, shadows, WS1 distance culling and FPS. The new stylized pine is taller/has different silhouette, so collision and visual ground clearance must be checked. No measured runtime performance or local build in GitHub-only editing.

**STG1 global tint (2026-10-30):** The current `Shaders/StylizedPineFoliage.gdshader` now reads `wm_foliage_tint` and `wm_foliage_tint_strength` from **Godot Project Settings → Shader Globals**, alongside the new `ForestGrass001` patch shader and DF2 canopy foliage. Bark is unchanged; the local `palette_response` and `foliage_roughness` remain per-tree-material. The loader no longer sets old material-local `forest_tint` fields. Source imported art and old GLB/procedural fallbacks unaffected. Set strength=0 for original vertex colours; runtime validation pending.

**GV1 current visibility rules:** Neither `PineSettings.cs` nor `PineMaster.tres` now contains `RenderDistance`, `LodDistance`, `DistanceFadeMargin`, `StylizedLod1Distance` or `StylizedLod2Distance`. These older documented distances below are historical implementation snapshots, not active settings. The world passes a common `VegetationVisibilityPolicy` to the pine placement controller: three stylized GLTF meshes choose LOD0/1/2 at 35%/70% of the fog-driven range, then vanish behind opaque fog plus the common safety band. Older procedural/GLB sources use the same first boundary with their available levels. Fog settings edits update native LOD ranges and chunk residency on events, without moving seeds or recalculating entire distribution.
