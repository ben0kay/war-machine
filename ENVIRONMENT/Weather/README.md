# TestWorld weather integration

Project-owned C# WeatherBridge instantiates the new weather_atmosphere addon's precipitation and atmosphere components through TestWeather.tscn. TestWeatherController.gd is a small subclass exposing a combined rain/snow preview state. Addon sources are unchanged. Sky3D keeps exclusive ownership of time, sunlight and fog (manage_environment=false; no addon sun reference).

EnvironmentMaster now owns enabled, independent rain/snow intensity, local mist, drifting motes, gusts, turbulence, particle size/fall speed and quality (0 Low / 1 Medium / 2 High). F9 applies changes immediately. Existing shared wind strength/speed and the new wind heading also feed precipitation and all plant materials. Rain and snow can coexist. Settings reset with F9 resets and runtime resource copies protect source masters. Clear weather is the default.

The addon is a useful prototype: layered GPU precipitation, quality budgets, mist, drifting particles, weather profiles/transitions, zones and optional lightning/audio. Integration limitations found in review: default particles anchor around y=0, idle component callbacks continue, splash placement assumes a flat ground plane, and its environment/sun ownership can compete with Sky3D. This bridge uses camera-height anchoring, disables inactive component/emitter processing and hides inactive emitters. Active weather still intentionally runs the addon's camera-follow/wind callbacks; no claim of zero CPU work while raining. Zero weather disables the entire effect subtree directly; reactivation wakes it explicitly. Large allocations remain bounded by the addon's quality tables.

Cave shelter is checked on explorer movement, with state reapplied only on shelter changes. Local rain/snow/mist/motes are suppressed within the cave. This is a local tunnel test, not a general roof/occlusion solution. Rain/snow outside do not collide individually with arbitrary roofs or terrain. Splash, lightning and audio components are not instantiated yet; snow accumulation and automatic storm/cloud/ground-wetness changes are not included. These need a separate, deliberate integration rather than blindly enabling every demo component.

Initial source/reference checks only; Godot/.NET are unavailable here. Test rain/snow separately and together, wind heading/strength, quality, zero/reactivation, cave shelter and FPS locally. No compiled/runtime/visual acceptance claimed.

## Close ground wisps (separate from distance fog)

F9 Ground haze (Forward+) now controls an animated noisy fog layer, **enabled by default** at density **0.18**, height **1.1m**, noise scale **0.35**, drift **0.3**, contrast **0.8**. The earlier saved default was OFF and its homogeneous boxes could not produce smoke-like wisps. Smaller noise-scale values make larger features. Increase contrast for more gaps/defined ribbons, density for stronger visibility, drift for faster motion. Height describes the layer above terrain, not camera altitude. Existing distance fog and weather mist controls stay independent.

Nine 8×8m FogVolumes overlap on a 6m tile grid around the explorer, covering close terrain rather than a 72m uniform blanket. Each tile samples height and a local tangent plane so density follows gentle slopes. Steep/invalid patches hide. `Shaders/GroundWisps.gdshader` uses two world-space value-noise layers, shader TIME drift and a soft height envelope concentrated near the feet; no billboard cloud cards or texture generation. One shader is shared, with nine small materials caching their height/slope. The fog-grid range is temporarily shortened to 48m to favour nearby detail. Sky3D's same Environment is reused, base volumetric density is zero, and no second sky/WorldEnvironment is added.

No C# Process/PhysicsProcess callback. Tile placement and terrain slopes update on tile crossings; shelter/altitude checks run only after 1.5m of movement or explicit mode/UI change. Standing still only has the intentional GPU fog animation. Hidden/sheltered/flying more than 35m above terrain (or below terrain outside the cave) hides all volumes and restores previous volumetric enable/density/range settings. OFF/zero frees volumes entirely and restores those values. Reinitialization/exit disconnect movement and camera-mode signals. The GPU volumetric pass has a cost while visible; no measured FPS/CPU/GPU claims.

Shader built-ins checked against [Godot's fog shader reference](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/fog_shader.html). Source, uniform bindings/resource references and whitespace checked; **no Godot/.NET executable is available here**, so shader compile and appearance are unverified. Locally run F5, switch F6 to first-person, look down/across the grass and wait to see drift. Try density/contrast/height, zero/OFF, re-enable, cave entry/exit, flight altitude and F9 Reset. Check for visible tile edges or reprojection trails. This is approximate local tangent-plane fog, not an exact sampled terrain volume; native froxel resolution limits very fine detail.
