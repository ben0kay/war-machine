# Gameplay HUD

> **Current implementation (2026-10-28):** `WorldController.InitializeHealthFeedback` now creates exactly one `HealthBarOverlay` under `GameplayHUD/Screen`, sharing the existing CanvasLayer with Hotbar. It automatically shows an overhead bar for injured shared-health entities and will show the player's bottom-left bar when PH0 provides actual HP. UI controls ignore the mouse. Full-health entities have no bars. Earlier planned-only lines below are historical.

In-game player interface composition lives here. The [Hotbar](Hotbar/README.md) is a purely visual nine-slot strip. HUD elements observe actor/inventory/equipment state, never become the source of truth. A future player health/status widget comes from [FEEDBACK/Bars/PlayerStatus](../../FEEDBACK/Bars/PlayerStatus/README.md) after [PLAYER PH0](../../PLAYER/IMPLEMENTATION_PLAN.md); reusable bar design is governed by [FEEDBACK's FB plan](../../FEEDBACK/IMPLEMENTATION_PLAN.md). Instantiate it as a **sibling** of the hotbar in the same shared world HUD, including the inherited FPS debug scene, without duplicate subscriptions or mouse input interception. No new UI is implemented by this documentation change.
